The section heading is “COMING SOON”, with the straight-line React Bits Text Loop treatment approved on 29 October 2026: https://reactbits.dev/text-animations/text-loop?shape=line. Following the PI’s clarification, use a compact warm-white banner with black text at the shared heading size, emphasis weight and normal letter spacing. It is a subdivision of Tools, not another page title. Reduce the gap after the released list to 32px on desktop and 24px on mobile. Two identical groups move left at 26 CSS pixels per second; the measured repeat count fills the viewport and makes the loop seam exact. The native button has a descriptive accessible label and a quiet underline for keyboard focus. The accessible heading occurs once; visual repeats are hidden from assistive technology. Offscreen and background-tab states pause playback, and dynamic reduced motion replaces the loop with one static, wrapping heading. Resize/font measurement preserves the shared type scale on mobile.

## Interaction and motion

`usePreviewClock` drives a finite sequence only while the mounted preview is visible and the document is foregrounded. Completed results hold. Pause/resume/replay controls belong to preview footers, never the changing section heading. Reduced motion starts at the finished result, with static chapter selection; live preference changes are respected.

TAIPAN shows immediate tracer movement and a heartbeat, followed by spatial maps. A visible slider explores tracer passage. Preview timing is an editorial choice, not a computation-speed claim.

Lumos receives explicit time messages inside an isolated same-origin HTML viewport. Both sides validate message origin/source. Its chapter controls start the relevant scene; reduced motion selects a representative still. The parent owns visibility and motion preferences; the iframe starts no independent animation timer. Fit the complete application bounds (1920×946, starting at y=92 in the source canvas), including its breadcrumb and lower controls. Remove the bottom explanation as requested; the fullscreen control lives in the window header. Fullscreen provides a larger view of the original GUI. Site controls retain shared typography; source-scene lettering scales with the original interface illustration.

GALAH opens with its greeting, then the user’s request appears beneath it. The answer grows as a dark assistant message in the same conversation. A React Bits Text Type-style fade reveals individual characters at a fixed rate, driven by requestAnimationFrame rather than word-by-word timers. Reserve each arriving word’s full width to prevent mid-word line jumps. The transcript follows new content with one continuous damped scroll adjustment, with native scroll anchoring disabled, while the composer stays at the bottom. Wheel or touch interaction pauses playback so visitors can read earlier messages. Hidden future messages/exports are not in the accessibility tree. Assistive technology gets the response as one labelled object rather than word-by-word announcements.
